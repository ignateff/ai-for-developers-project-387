# Локализация сообщений GitHub Actions

Задача: [#106](https://github.com/ignateff/ai-for-developers-project-387/issues/106).

Пользовательские сообщения workflow должны быть на русском языке: комментарии в
issues и PR, предупреждения, описания параметров ручного запуска и, где это
безопасно, отображаемые названия workflow, jobs и шагов. Машинно читаемые
идентификаторы, имена файлов, outputs, маркеры, коды причин, переменные
окружения, ссылки и пути не переводятся.

## Перечень workflow

## Вызываемые скрипты

| Скрипт                                  | Пользовательский текст                                                | Решение                                                                                                                |
| --------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `scripts/opencode-command.ts`           | `instructions.md` для агента `/oc`.                                   | Добавлено требование писать пользовательские объяснения по-русски; Conventional Commits и `Refs` остаются английскими. |
| `scripts/opencode-actions-budget.ts`    | Не публикует текст; читает имя job и шага допуска из истории Actions. | Идентификаторы не изменены.                                                                                            |
| `scripts/opencode-review.ts`            | Промпт ревьюера.                                                      | Уже требует русский текст; оставлено без изменения.                                                                    |
| `scripts/opencode-review-workflow.ts`   | Ограничения и контекст ревью.                                         | Пользовательские ограничения уже на русском; технические причины для модели не переводятся.                            |
| `scripts/opencode-review-publish.ts`    | Заголовок, предупреждения и ошибки публикации.                        | Уже на русском; маркер `<!-- opencode-review-report:... -->` сохранён.                                                 |
| `scripts/opencode-budget-workflow.ts`   | Служебный комментарий бюджета.                                        | Содержит только маркер и JSON; пользовательского английского текста нет.                                               |
| `scripts/opencode-budget-lock.ts`       | Служебный комментарий блокировки.                                     | Содержит только маркер и UUID.                                                                                         |
| `scripts/opencode-log-summary.ts`       | Техническая сводка лога Actions.                                      | Остаётся технической и машинно читаемой; не является публикацией в issue или PR.                                       |
| `scripts/opencode-github-diagnostic.ts` | Технические строки диагностики.                                       | Остаются техническими; workflow и шаги переведены.                                                                     |

## Машинно читаемые значения, которые нельзя переводить

- Обязательная проверка защиты `main`: job `check` в `ci.yml` (контекст `check`, GitHub Actions).
- История бюджета команд: имя job `opencode-command-v2-pr-<number>` и шаг
  `Record command admission v2`; их читает `scripts/opencode-actions-budget.ts`.
- Маркеры: `<!-- opencode-review-report:... -->`,
  `<!-- opencode-pr-attempt-budget:v1 -->`, `<!-- opencode-pr-budget-lock:v1 -->`.
- Артефакты: `lighthouse-report`, `head-browser-<SHA>`, `review-<run>-<attempt>`.
- Коды причин `/oc`: `timeout`, `limit_exhausted`, `infra`, `agent_failed`,
  `unknown`; outputs `report`, `number`, `sha`, `artifact`, `reason`.
- Учебный заголовок `[TRAINING] Lighthouse LCP example` — фиксированный
  идентификатор поиска, даже в русском ответе.
- Параметры `app_url` и `training`, пути, URL, названия метрик `LCP`, `CLS`, `INP`.

## Совместимость с прежними результатами

- Старые английские ограничения ревью по-прежнему распознаются при повторной
  публикации: `formatReviewBody` проверяет и английские, и русские слова.
- Старые попытки `/oc` учитываются, потому что имя job и шага допуска не
  изменилось.
- Промпты ручного и планового аудита требуют искать открытые и закрытые
  задачи, включая прежние английские, и переиспользовать их вместо создания
  русских дубликатов. Повторный комментарий допускается только при новом
  свидетельстве или изменившемся результате.
- Учебная задача ищется по точному английскому заголовку среди открытых и
  закрытых задач.

## Тексты вне контроля проекта

- Собственные сообщения `actions/checkout`, `actions/setup-node`,
  `actions/upload-artifact`, `actions/download-artifact`, `actions/github-script`,
  `actions/create-github-app-token`, `jdx/mise-action`, `hexlet/project-action`.
- Release PR, changelog, теги и GitHub Release, которые формирует
  `googleapis/release-please-action`; язык задаётся самим action и английскими
  сообщениями коммитов проекта.
- Пометка в ручном навыке `triage` (`.agents/skills/triage/SKILL.md`) остаётся
  английской: навыки Matt Pocock сохраняются как есть по правилу проекта.
  Изменена только автоматическая публикация `opencode-triage.yml`.
- Вывод Lighthouse, GitHub UI, аннотации проверок, страницы ошибок GitHub и
  служебные логи runner.
- Служебные сообщения и логи самого OpenCode runtime и upstream handler.
- Язык ответа реальной модели: промпт требует русский текст, но тесты с
  заглушками этого не гарантируют.

## Проверка после слияния

1. Открыть тестовую задачу и выполнить `/oc` с безопасным заданием; проверить,
   что комментарий об ошибке (при контролируемом сбое) и объяснения агента
   на русском, а коммит остаётся Conventional Commits на английском.
2. Открыть тестовую задачу без меток и проверить русский ответ триажа и точную
   пометку `> *Сгенерировано ИИ в ходе триажа.*`.
3. Запустить аудит производительности вручную с `training: true`; убедиться,
   что задача использует точный заголовок `[TRAINING] Lighthouse LCP example`,
   не создаёт дубликат и не повторяет неизменённый комментарий.
4. Проверить отчёт автоматического ревью на русском и сохранение SHA и ссылки
   на Actions.
5. Убедиться, что required check `check` по-прежнему запускается и проходит.
