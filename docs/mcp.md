# MCP-эндпоинт для агентов

Сервис отдаёт Model Context Protocol по адресу `POST /mcp`, в том же процессе и контейнере, что и HTTP API: агент работает с календарём без отдельного сервиса и без доступа к базе.

- Продакшен: `https://call-calendar-k7f2.fly.dev/mcp`
- Локально после `mise run dev`: `http://localhost:3000/mcp`; если порт занят, используйте адрес API, напечатанный при запуске.

Эндпоинт не входит в TypeSpec-контракт и не описывается в OpenAPI: MCP — отдельный протокол, а не HTTP-операция предметной области.

## Инструменты

Ровно два инструмента: чтение доступности и создание записи. Предстоящие события и удаление недоступны, поэтому контакты гостей через MCP не читаются.

### `get_availability`

Параметр `date` (`YYYY-MM-DD`, UTC) необязателен.

- Без `date` — обзор 14-дневного UTC-окна: для каждого типа встречи даты и число свободных слотов.
- С `date` — слоты выбранного дня для каждого типа встречи. Даты вне окна возвращают ошибку `DATE_OUT_OF_RANGE`, неверный формат — `INVALID_DATE`.

`meetingTypeId` для записи агент берёт из этого же ответа; отдельного списка типов встреч нет.

### `create_booking`

Поля: `meetingTypeId`, `startsAt` (UTC, ISO 8601 с `Z`), `guestName`, `guestEmail`.

- Актуальную версию типа встречи MCP определяет сам, агенту не нужно её передавать.
- `Idempotency-Key` выводится из типа встречи, слота и почты гостя: повторный вызов с теми же данными возвращает ту же запись, а не создаёт вторую.
- Успех возвращает запись целиком: `id`, `startsAt`, `endsAt`, название и длительность типа встречи, данные гостя.

Ошибки приходят как результат с `isError: true`: `{code, hint}`, где `hint` подсказывает следующий шаг; для `VALIDATION_ERROR` разбивка по полям лежит в `details`.

| Код                      | Когда                                                         |
| ------------------------ | ------------------------------------------------------------- |
| `VALIDATION_ERROR`       | Некорректные поля; `details` повторяет разбивку HTTP API      |
| `MEETING_TYPE_CHANGED`   | Тип встречи удалён, изменён или не существует                 |
| `SLOT_UNAVAILABLE`       | Слот уже занят — нужно предложить другое время                |
| `IDEMPOTENCY_KEY_REUSED` | Та же почта уже записана на этот слот с другими данными гостя |
| `DATABASE_BUSY`          | База занята другой записью — повторите тот же вызов позже     |

## Подключение

OpenCode (`opencode.json` или глобальная конфигурация):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "calendar": {
        "type": "remote",
        "url": "https://call-calendar-k7f2.fly.dev/mcp"
      }
    }
  }
}
```

Другие клиенты с поддержкой удалённого HTTP-транспорта используют тот же URL:

```json
{
  "mcpServers": {
    "calendar": {
      "type": "http",
      "url": "https://call-calendar-k7f2.fly.dev/mcp"
    }
  }
}
```

Шаблон для репозитория лежит в [`opencode.example.json`](../opencode.example.json). Внимание: проектную конфигурацию проверяет `scripts/opencode-discovery.ts` перед запуском GitHub-агента; локальный MCP-сервер или плагины в `opencode.json` эту проверку не пройдут. Держите личные настройки вне репозитория.

## Ограничения

- **Авторизации нет.** Эндпоинт открыт, как и HTTP API: любой может прочитать доступность и создать запись. Это не расширяет доступ к данным — предстоящие события через MCP не читаются, — но слоты можно занять скриптом. Ограничения частоты нет.
- **Только UTC.** Слоты, даты и `startsAt` — в UTC; перевод в местное время выполняет агент.
- **Окно 14 дней.** Запись возможна только в это окно и только на слот, который вернул `get_availability`.
- **Холодный старт.** У приложения на Fly `min_machines_running = 0`, поэтому первый вызов после простоя ждёт запуск машины.

## Проверка вручную

```bash
curl -s -X POST http://localhost:3000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Ответ приходит одним SSE-событием `message` с результатом `tools/list`.
