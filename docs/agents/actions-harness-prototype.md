# Actions admission fixture prototype (#41)

This is **not an authorization boundary** and is not connected to a workflow or model. `mise run actions:harness` reads one JSON fixture from standard input and uses only its `responses` map, keyed by GitHub REST path and query; missing responses fail closed. `mise run test:actions-experiment` exercises it and the earlier inspectors. The fixture process cannot make a network request. The `trusted` flag and event payload are fixture inputs, not verified GitHub identity or trust.

The proposed history protocol uses a dedicated workflow, a retained boundary sentinel run, and jobs named `budget-model / command / pr-N` or `budget-model / review / pr-N`. A successful `admission` step would mark an admitted model job before runtime preparation. Jobs are deduplicated by ID across attempt listings, so a publication-only rerun does not automatically spend another attempt. Each model-job rerun needs a new admission step. History errors, inconsistent pages, missing boundary and ambiguous marker metadata produce `infra`. Evidence links identify counted attempts, not proven real runs.

This code is deliberately only a partial prototype. In particular, it does **not** implement the workflow that binds job names to authentic event payloads, validates trust, emits the marker at the right time, or prevents reuse of an old admission on rerun. No local fixture proves those properties. The sentinel detects its own absence, not deletion of individual later runs; the protocol requires preserved complete history and restricted deletion permissions. Listing and marker visibility under cancellation, reruns, queued jobs, concurrent pagination, and actual token permissions remain unverified. The prototype can return `admit` while a marker is unavailable, so this result must never authorize runtime preparation or a model call. Concurrent admission and cancellation can undercount even in the intended design; #39 explicitly accepts that risk, not silent API errors or incomplete history.

Before any model integration, build and test the complete externally observable workflow contour; obtain separate user authorization for metadata-only GitHub Actions experiments and verification of every token, including the exchanged App token; record actual event binding, step/job visibility, rerun, cancellation, history retention and permissions evidence. Do not publish token values. If these cannot establish the requirements, keep #41 open and dependent model workflows blocked; an external database needs a separate human decision.
