# Actions admission experiment (#41)

`scripts/actions-admission.ts` is a **metadata inspector, not a budget or an authorization gate**. It always returns `infra`; no workflow or model uses it. Its candidate marker is a successful `admission` step in a job named `model`, in one explicitly supplied run attempt. That name is an experimental fixture, not an established durable admission record. A matching step does not prove admission, PR identity, exclusivity, or safe use of the token. An absent marker only describes the returned jobs, not the absence of a consumed attempt.

The inspector requests attempt-specific jobs, verifies page counts and unique job IDs, and returns a constructed run-attempt link without logging credentials or API responses. It refuses incomplete pages and API failures. It does not enumerate workflow runs, resolve PRs, check trust, calculate either budget, perform locking, or allocate an attempt. Job/step names, timing, job-rerun semantics, and whether an in-progress step is durable enough need a separately authorized real GitHub experiment before they can be used as an accounting protocol. A completed successful step may be too late to record a cancellation immediately after admission; this is not solved here.

## Blockers before a model gate

- Establish reliable PR identity for both comment channels and PR events, including older run attempts, without assuming `pull_requests`, SHA or titles provide it. Establish a start boundary and completeness for all relevant history; no silent reset is allowed.
- Prove atomic serialization across admissions and cancellation, including queued runs and overlapping attempts. Determine a durable admission marker before runtime preparation and prevent reuse by partial job reruns; publication-only reruns must not allocate. A successful old budget job alone is not an authorization.
- Enumerate all applicable workflow runs and attempts, distinguish rejected events and the two budgets, and verify completeness under retention and deletion. GitHub's filtered workflow-run search is limited to 1,000 results; reaching or exceeding that bound, or any uncertain truncation, must fail closed or use a separately proven complete partitioning strategy. This inspector does not implement run listing.
- GitHub supports deleting workflow runs for principals with sufficient write authority. YAML permissions and fixtures do not establish that every token accessible to the agent, including an exchanged App token, lacks that authority. Verify effective permissions separately, without publishing credentials. Administrators and authorized deleters can alter history; retention or deletion invalidates completeness.
- Obtain explicit authorization for metadata-only runs covering both comment channels, automatic review, cancellation, concurrent events, full rerun, model-job-only rerun, and publication-only rerun. Record safe links and observed metadata. No such authorization or evidence is present here.
- Implement and test the actual decision/grounds boundary, independent three-attempt budgets, trust and event handling, historical boundary, pagination and failure cases. Then integrate the required checks. If these properties cannot be established, keep the model blocked; an external database requires a new human decision.

Local fixtures exercise the inspector, not GitHub's real retention, token permissions, event binding, concurrency, or rerun behavior. Issue #41 remains open.
